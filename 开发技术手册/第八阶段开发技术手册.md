## 一、先说简单结论

前七个阶段已经完成了可靠数据、账号隔离、最小 Agent Harness、记忆与安全、主动陪伴、产品埋点、学习总结以及数据权利能力。第八阶段不再继续无条件堆叠功能，而是进入 P3：

```text
第七阶段数据验证
→ 选择一个真实问题
→ 小范围、可关闭、可回滚地验证
→ 通过指标和人工反馈决定是否扩大
```

P3 的默认交付物是“候选功能验证能力”和“是否继续投入的证据”，不是一次性上线所有长期功能。除非产品方针对某一轨道另行确认，本手册不授权修改业务代码、迁移数据库、接入外部通知/社交服务、连接真实用户数据或部署生产环境。

## 二、排期依据与前置条件

### 2.1 排期中的 P3 候选功能

| 候选 | 排期定位 | 开发前必须满足的条件 | 本手册轨道 |
|---|---|---|---|
| 成就徽章 | 长期激励 | 用户确实需要额外激励，且不会制造打卡压力 | P3-A |
| 自定义专注时长 | 体验增强 | 默认 25 分钟无法覆盖主要用户习惯 | P3-B |
| 学习提醒 | 主动触达 | 用户主动订阅，且有可靠通知渠道 | P3-C |
| 搭子播报周报 | 多模态总结 | 周报打开率和语音使用率证明有价值 | P3-D |
| 更丰富的搭子形象 | 陪伴体验 | 留存问题与视觉陪伴感有关 | P3-E |
| Live2D/数字人 | 高成本视觉 | 静态形象限制已被数据验证，成本可接受 | P3-F |
| 多人自习室 | 社交协作 | 单人陪伴闭环稳定且有明确多人需求 | P3-G |

### 2.2 进入 P3 的硬性条件

- 第七阶段自动测试、主流程 E2E、隐私和数据权利验收已完成，遗留事项有明确负责人和截止条件。
- P2 事件、指标、总结和数据删除策略可以由数据库事实复算。
- PostgreSQL 隔离实库、备份恢复、并发和迁移回滚已完成，或明确声明本次只在隔离 SQLite 环境验证。
- 已取得产品方对候选轨道、实验用户范围、数据保留和外部服务边界的书面确认。
- 真实模型、TTS、推送或第三方服务只在单独授权后使用，不得混入普通自动测试。

### 2.3 本阶段不解决的问题

- 不把所有候选功能合并为一个大版本，不同时引入成就、提醒、社交和数字人。
- 不建设公开排行榜、社交关系图谱、复杂任务管理或社区内容审核系统。
- 不默认接入短信、邮件、系统推送、日历、广告或营销平台。
- 不引入 Live2D、实时数字人口型、视频会议或多人语音，除非对应轨道单独通过技术和隐私评审。
- 不改变 P1-C 的危机安全、长期记忆白名单、Agent 权限和轨迹脱敏规则。
- 不让模型决定徽章授予、专注时长、通知订阅、用户可见范围或数据删除范围。
- 不将实验指标当作生产事实，不用前端本地状态替代后端学习记录。

## 三、阶段目标与成功标准

### 3.1 用户侧目标

- 用户清楚知道某项增强功能是否开启，并可随时关闭。
- 新功能不会影响登录、聊天、专注、统计、总结和数据删除主链路。
- 激励是可选的，不制造连续打卡、排名或失败羞耻感。
- 提醒只发送给明确订阅且仍在有效授权范围内的用户。
- 自定义时长、语音播报和形象增强失败时，用户仍能完成学习。

### 3.2 产品侧目标

- 每条候选轨道都有明确假设、实验人群、主指标、护栏指标和停止条件。
- 能区分功能被展示、被开启、被使用、被关闭和产生实际学习价值。
- 能从实验结果判断继续、调整、暂停或永久放弃，而不是凭主观偏好推进。

### 3.3 P3 最低完成标准

1. 候选功能先经过数据和隐私评审，再进入隔离实验。
2. 所有新事件使用固定白名单、版本号和用户隔离。
3. 所有高影响动作具有可关闭、幂等、限流和回滚方案。
4. 任何外部触达都具备订阅证明、撤回入口、失败重试边界和服务商披露。
5. 实验结束后形成验收记录，明确是否进入下一轮，而不是默认视为“开发完成”。

## 四、统一实验框架

### 4.1 候选轨道生命周期

```text
待评审
  → 通过进入条件
  → 方案设计
  → 隔离实验
  → 待验收
  → 继续 / 调整 / 暂停 / 放弃
```

“已完成”必须表示该轨道的实验结论已经产生；不能只表示代码已经写完。

### 4.2 实验卡片

每个轨道开发前必须填写：

```text
problem_statement       # 要解决的真实问题
hypothesis              # 可被数据证伪的假设
target_cohort           # 实验用户范围
primary_metric          # 主指标及分母
guardrail_metrics       # 留存、投诉、关闭率、失败率等护栏
minimum_sample          # 最小样本或观察窗口
privacy_impact          # 新增数据及服务商流向
kill_switch             # 一键关闭方式
rollback_plan           # 数据和代码回滚
owner_and_approval      # 产品、安全、技术确认记录
```

### 4.3 事件与实验隔离

- 复用第七阶段脱敏事件体系，事件名必须是固定枚举，不接受前端自由拼接。
- 新事件至少包含 `event_id`、`user_key`、`event_type`、`occurred_at`、`source`、`schema_version`、`experiment_id`。
- 禁止写入密码、Token、邀请码、API Key、完整聊天正文、危机原文、原始音频和供应商凭证。
- 实验分组必须在后端确定并可复算；不能由客户端参数自行声明“我是实验组”。
- 删除学习数据、账号注销或撤回实验同意后，相关实验记录必须按数据声明失效或删除。

### 4.4 统一开关与停止机制

每个轨道至少支持：

- 全局 kill switch；
- 按实验 ID 关闭；
- 按用户关闭；
- 关闭后的既有缓存失效策略；
- 关闭原因和操作者的脱敏审计记录。

停止功能时不得删除学习事实，不得阻塞用户正常学习，不得以静默降级掩盖失败。

## 五、P3-A：成就徽章与温和激励

### 5.1 目标与范围

只验证用户是否需要“可回顾的里程碑”，首版限于基于真实学习事实的非竞争性徽章，例如完成首个专注、累计学习时长达到阈值、完成一周目标。不得引入公开排名、连续打卡惩罚或社交比较。

### 5.2 规则边界

- 徽章由确定性规则引擎根据已结算记录授予，模型只能生成说明文字。
- 同一用户、同一徽章、同一规则版本只授予一次，必须幂等。
- 规则版本变更不得篡改历史授予记录；纠错采用撤销/重算记录。
- 用户可隐藏徽章和关闭激励提示；隐藏不删除学习事实。
- 危机安全状态、异常数据或正在删除的数据不得触发激励文案。

### 5.3 建议数据结构

```text
achievement_definitions(id, code, rule_version, title, description, active)
user_achievements(id, user_id, achievement_id, awarded_at, source_event_id, hidden_at)
```

不得保存通过模型推断的性格、能力、健康或教育效果结论。

### 5.4 验收重点

- 重复请求、刷新和并发结算不会重复授予。
- 修改或删除学习数据后，徽章显示与声明一致。
- 关闭激励后不再展示主动徽章提示，但历史数据仍可按用户选择查看。
- 激励文案不使用“落后”“失败”“必须坚持”等施压表达。

## 六、P3-B：自定义专注时长

### 6.1 目标与范围

验证不同用户是否需要 25 分钟之外的专注时长。首版只允许选择产品批准的有限档位（例如 15、25、45、60 分钟），不允许任意输入超长时长。

### 6.2 技术边界

- 时长在开始专注前确定并写入 `study_session`，中途不能由模型修改。
- 计时、暂停、恢复、过期补结算和幂等规则沿用 P0-B02。
- 用户选择不等于完成；统计按实际有效时长和结算状态计算。
- 不因选择短时长而降低安全检查，不因选择长时长而自动增加提醒。

### 6.3 验收重点

- 刷新、关闭页面和跨时区恢复仍正确。
- 非法档位、负数、极端值和篡改请求被拒绝。
- 同一 `sessionId` 只能结算一次，旧客户端不会覆盖新规则。
- 自定义时长关闭后，新会话回退到默认值，历史记录仍可读取。

## 七、P3-C：用户主动订阅的学习提醒

### 7.1 默认方案

首版优先验证站内提醒；若要接入系统推送、邮件或短信，必须单独完成供应商、权限、数据流向、费用、失败重试和隐私评估。默认关闭，不能通过登录或聊天隐式订阅。

### 7.2 订阅协议

订阅记录至少包含渠道、频率、安静时段、时区、确认时间、撤回时间、协议版本和来源。每次发送都必须验证订阅仍有效，并提供一键关闭入口。

### 7.3 触达边界

- 后端规则决定是否进入提醒队列，模型不得决定发送时间、频率或订阅状态。
- 同类提醒按用户和周期幂等，具有冷却窗口和最大频率。
- 发送失败记录失败，不显示已送达；站内打开时可提供降级提示。
- 危机内容、敏感情绪和学习失败不得被转化为营销式触达。

### 7.4 停止条件

投诉、关闭率异常升高、渠道不可达、撤回入口失效或无法证明订阅来源时，立即关闭外部触达，回退到站内主动查看。

## 八、P3-D：搭子播报周报

### 8.1 依赖与范围

依赖第七阶段学习总结事实层。程序先生成事实卡片，模型只组织语言，TTS 只在用户开启语音且主动请求或明确订阅后执行。不得把播报作为新的学习事实来源。

### 8.2 数据和音频边界

- 播报文本只使用已确认的周报事实、用户允许的语气偏好和必要设置。
- 默认不保存原始音频；如服务商需要发送文本，必须在隐私说明中披露。
- TTS 失败时保留文字周报，不能影响学习记录和总结缓存。
- 删除总结或账号注销时，关联的临时音频和任务元数据按保留策略清理。

### 8.3 验收重点

- 播报数字与事实卡片逐项一致。
- 关闭语音后不再发起 TTS 请求，旧请求被取消或结果被丢弃。
- 模型生成失败、音频失败和网络超时均有本地文字降级。
- 周报不会推断心理状态、学习能力或未来成绩。

## 九、P3-E/P3-F：形象、轻动画与数字人候选

### 9.1 静态形象和轻动画

优先验证低成本、可访问的静态图片或 CSS/Canvas 轻动画。动画不得阻塞计时、聊天、语音和屏幕阅读器；必须提供减少动态效果选项，并在低性能设备上自动降级。

### 9.2 Live2D/数字人单独立项条件

只有在以下条件全部满足后才允许另行立项：

- P2 数据表明视觉陪伴是留存或使用价值的主要瓶颈；
- 静态形象和轻动画实验已经完成且效果不足；
- 已完成素材版权、客户端性能、隐私、网络带宽和成本评估；
- 明确不采集或长期保存不必要的人脸、声音、生物特征数据。

本阶段不得直接接入数字人 SDK 或上传用户原始音视频。

## 十、P3-G：多人自习室候选

### 10.1 为什么必须最后评估

多人自习室会引入成员身份、房间权限、实时状态、举报、封禁和隐私泄露风险，不能因为“看起来有趣”就与单人陪伴同时开发。必须先证明单人核心闭环稳定且存在明确多人需求。

### 10.2 最小可行边界

如通过立项评审，首版应从临时、低信息量的房间开始：

- 房间短生命周期、明确创建者和加入权限；
- 只共享在线/专注状态，不共享聊天原文、长期记忆、目标详情或个人联系方式；
- 不默认开放陌生人私聊、文件上传、语音视频和公开排行榜；
- 房间关闭、成员退出和举报路径可用，异常时可全局停用。

### 10.3 必须补齐的安全设计

- 房间和成员级鉴权、越权测试、速率限制和审计；
- 举报、屏蔽、封禁和人工处理流程；
- 未成年人和敏感内容风险评估；
- WebSocket/实时通道断线、重连和状态过期策略；
- 数据保留、导出、删除和注销的关系处理。

## 十一、Agent、权限与数据边界

| 操作 | 模型可见 | 自动执行 | 用户确认 | 可信系统专用 |
|---|---:|---:|---:|---:|
| 读取候选功能设置 | 可 | 是 | 否 | 否 |
| 修改设置或订阅 | 可申请 | 否 | 是 | 否 |
| 判断徽章是否达成 | 不可决定 | 规则引擎 | 否 | 是 |
| 决定提醒时间/频率 | 不可决定 | 规则引擎 | 订阅时已确认 | 是 |
| 生成周报或播报文案 | 可申请 | 受限 | 用户主动请求或已订阅 | 否 |
| 创建/加入自习室 | 可申请 | 否 | 是 | 是（权限服务） |
| 改变学习事实 | 不可直接执行 | 否 | 必要时确认 | 是（学习服务） |
| 删除、导出、注销数据 | 不可直接执行 | 否 | 二次确认 | 是（数据权利服务） |

继续遵守第六、七阶段原则：程序决定事实、权限和触达；模型只生成表达；危机安全流程优先于所有激励、提醒和社交能力。

## 十三、测试计划

### 13.1 通用实验测试

- 分组稳定、用户隔离、事件白名单、版本兼容和 kill switch。
- 关闭实验后缓存失效，既有学习事实不受影响。
- 重复请求、并发请求、时区变化和旧客户端请求的幂等行为。
- 删除、导出、注销后实验数据和关联资源的处理。

### 13.2 候选功能测试

- 徽章：规则边界、重复授予、隐藏、撤销和压力文案检查。
- 时长：合法档位、非法输入、计时恢复、过期补结算和统计一致性。
- 提醒：订阅证明、撤回、安静时段、冷却、失败和站内降级。
- 周报播报：事实一致、TTS 开关、失败降级、临时音频清理。
- 形象：无障碍、低性能降级、减少动态效果和资源加载失败。
- 自习室：房间鉴权、越权、断线重连、举报封禁和隐私隔离。

### 13.3 统一验证

```bash
./scripts/verify.sh
```

自动测试继续使用临时 SQLite、匿名测试账号、假模型和 TTS 拦截；涉及通知、真实模型、真实音频、PostgreSQL 或多人实时通道的验证必须在隔离环境单独执行并记录授权。

## 十四、人工验收与发布门槛

### 14.1 人工验收顺序

1. 查看实验说明、数据流和关闭入口，确认用户能理解并撤回。
2. 用隔离账号验证默认关闭、开启、刷新恢复和跨页面一致性。
3. 验证主流程：登录 → 设置目标 → 专注 → 结算 → 统计/总结不受影响。
4. 验证异常：服务失败、重复点击、断网、过期状态和 kill switch。
5. 检查导出、删除、注销与新增数据的关系处理。
6. 复核指标、投诉/关闭率和实验结论，形成对应验收记录。

### 14.2 发布门槛

- 候选轨道有产品、安全、技术和隐私确认。
- 自动测试、人工主流程和专项安全测试全部通过。
- 指标分母、观察窗口、样本量和停止阈值可复核。
- 外部服务（如有）完成供应商、密钥、费用、数据流向和降级评估。
- 有全局关闭、数据回滚和用户沟通方案。
- 第七阶段遗留的 PostgreSQL、真实模型/TTS 和隐私验收不被 P3 实验冒充完成。

## 十五、风险、停止条件与回滚

| 风险/停止条件 | 处理方式 |
|---|---|
| 激励导致明显压力、投诉或异常打卡 | 立即关闭徽章提示，保留用户主动查看和学习事实 |
| 自定义时长造成统计或计时不一致 | 关闭新档位，回退默认时长，不改写历史结算 |
| 提醒撤回失效、误发或渠道不稳定 | 立即停止外部发送，回退站内提醒并清理待发队列 |
| 周报出现虚构数字或敏感推断 | 禁止播报，只展示程序事实卡片和固定模板 |
| 动画影响性能、可访问性或学习完成率 | 自动降级静态形象，保留关闭入口 |
| 自习室出现越权、骚扰或隐私泄露 | 关闭房间入口，隔离受影响数据并启动审计 |
| 实验指标无法复算或分母漂移 | 暂停对外结论，修复事实层和事件版本 |

回滚优先采用功能开关、版本回退和队列停止；不得用不可逆批量删除掩盖实验问题。
