## 一、先用简单的话说明这一阶段

第四阶段开始把“会聊天的 AI 应用”升级成“具备 Agent 基础结构的产品”。

但这一阶段不会马上让 AI 自动操作产品，而是先建设四样基础设施：

| 技术名称 | 小白理解 | 作用 |
|---|---|---|
| 输入输出协议 | 统一表格 | 规定 AI 能看到什么、必须按什么格式回答 |
| 工具注册表 | 工具清单 | 规定 AI 未来可以申请使用哪些产品能力 |
| 状态观察器 | 给 AI 的简要小抄 | 只整理当前任务需要的目标、计时和统计 |
| 权限判断器 | 门卫 | 决定某个动作可以执行、需要确认，还是必须拒绝 |

完成后的变化是：

```text
现在
用户消息 → 模型 → 一段文字

第四阶段后
用户消息 + 必要学习状态
→ 严格协议
→ 工具白名单和权限检查
→ 安全的文字与动作结构
```

真正的 Agent 多轮循环，也就是“模型判断 → 调工具 → 看结果 → 再判断”，属于第五阶段 P1-B。本阶段只把它依赖的地基建好。

## 二、第四阶段范围

根据《开发排期手册》，本阶段只包含以下四项：

| 顺序 | 编号 | 需求 | 完成结果 |
|---:|---|---|---|
| 1 | P1-A01 | 定义 Agent 输入和输出协议 | 前后端对消息、工具和动作格式理解一致 |
| 2 | P1-A02 | 建立 Agent 工具注册表 | 所有允许的工具通过统一入口管理 |
| 3 | P1-A03 | 建立状态观察器 | AI 只能看到完成当前任务所需的最小状态 |
| 4 | P1-A04 | 建立 Agent 工具权限 | 动作由程序判断权限，不能只相信 Prompt |

开发顺序：

```text
确认第四阶段手册
→ 从第三阶段提交创建 P1-A 分支
→ P1-A01 协议
→ P1-A02 工具注册表
→ P1-A03 状态观察器
→ P1-A04 权限判断器
→ 自动测试与人工验收
→ 生成第四阶段验收记录
```

P1-A03 和 P1-A04 都依赖工具注册表。不得先让模型调用工具，再补权限。

## 三、本阶段明确不做什么

以下内容不属于第四阶段：

- 不实现多轮 Agent 循环。
- 不让现有 `/api/v1/chat` 自动执行工具。
- 不让 AI 直接开始、暂停或结算番茄钟。
- 不让 AI 直接修改学习历史或番茄数量。
- 不开发长期记忆和聊天摘要。
- 不保存完整 Agent 运行轨迹到数据库。
- 不开发情绪危机识别流程。
- 不开发主动提醒、学习周报或运营埋点。
- 不接入 MCP、Shell、任意文件读写或任意网络工具。
- 不引入 LangChain、AutoGen 等大型 Agent 框架。
- 不更换 FastAPI、Next.js、SQLAlchemy 或现有模型服务。
- 不进行生产部署、生产数据迁移或真实用户数据操作。

这些内容分别属于 P1-B、P1-C、P2 或单独的生产发布流程。

本阶段继续使用：

## 六、P1-A01：Agent 输入和输出协议

### 6.1 协议原则

所有协议必须：

- 有固定版本号，例如 `1.0`。
- 由 Pydantic 强校验。
- 默认拒绝未知字段。
- 对文字长度、数组数量、数字范围和枚举值设上限。
- 后端生成用户 ID、请求 ID和权限上下文，不能接受模型伪造。
- 模型输出校验失败时整包拒绝，不执行其中任何动作。
- 失败后返回普通本地陪伴文字，动作列表为空。

### 6.2 可信上下文与模型可见上下文分开

必须区分两类信息：

| 类型 | 内容 | 是否发给模型 |
|---|---|---:|
| 可信执行上下文 | 用户 ID、请求 ID、来源、权限证据、数据库 Session | 否 |
| 模型观察上下文 | 最新消息、今日目标、计时摘要、统计、必要偏好 | 是 |

Token、密码哈希、邀请码摘要、数据库地址和完整账号信息永远不能出现在模型上下文中。

### 6.3 推荐输入结构

示意结构：

```json
{
  "protocolVersion": "1.0",
  "message": "我想开始学习了",
  "conversationSummary": "",
  "state": {
    "goal": {
      "date": "2026-09-09",
      "text": "背 50 个单词"
    },
    "focus": {
      "status": "idle",
      "mode": "focus",
      "remainingSeconds": 0
    },
    "stats": {
      "todayTomato": 2,
      "todayMinutes": 50,
      "streak": 3,
      "weekStudyDays": 2
    },
    "preferences": {
      "buddyGender": "male",
      "voiceEnabled": false
    }
  }
}
```

限制建议：

| 字段 | 限制 |
|---|---|
| `protocolVersion` | 只接受明确支持的版本 |
| `message` | 1～200 字符，沿用当前聊天限制 |
| `conversationSummary` | 本阶段保持为空；协议允许最多 1000 字符供 P1-C 使用 |
| `goal.text` | 最多 60 字符 |
| `remainingSeconds` | 0～43200 |
| 统计数字 | 非负整数并设置合理上限 |
| 偏好 | 只接受白名单枚举和布尔值 |

### 6.4 推荐最终响应结构

```json
{
  "protocolVersion": "1.0",
  "requestId": "服务端生成的请求编号",
  "reply": "我们先专注 25 分钟吗？",
  "source": "llm",
  "actions": [
    {
      "type": "confirm_start_focus",
      "durationMinutes": 25
    }
  ]
}
```

规则：

- `reply` 必须存在，最长建议 500 字符。
- `source` 只允许 `llm` 或 `local`。
- 单次最多返回 3 个前端动作。
- 动作必须使用可区分联合类型，不使用任意字典。
- 未知动作导致整个结构校验失败。
- 本阶段只定义和测试动作结构，不接入正式页面执行。

### 6.5 模型内部决定结构

模型内部输出必须区分“最终回复”和“申请调用工具”：

```json
{
  "kind": "tool_call",
  "toolName": "get_today_goal",
  "arguments": {}
}
```

或：

```json
{
  "kind": "final_response",
  "reply": "今天的目标已经很清楚啦。",
  "actions": []
}
```

不能通过是否存在某个模糊字段来猜测模型意图。

### 6.6 前端动作白名单

P1-A 只定义第一版动作：

| 动作 | 参数 | 本阶段是否执行 |
|---|---|---:|
| `confirm_start_focus` | `durationMinutes` | 否，只定义协议 |
| `confirm_pause_focus` | 无 | 否，只定义协议 |

修改目标和偏好优先通过后端工具返回明确结果，不在本阶段增加“前端直接改数据库”的动作。

### 6.7 协议降级

发生以下情况时，统一降级为：

```json
{
  "protocolVersion": "1.0",
  "requestId": "服务端请求编号",
  "reply": "我这边刚刚走神了，我们继续聊聊吧。",
  "source": "local",
  "actions": []
}
```

需要降级的情况：

- 模型返回非 JSON。
- 缺少必填字段。
- 输出未知工具或未知动作。
- 参数超出范围。
- 工具结果格式错误。
- 协议版本不支持。

不得只删除危险字段后继续执行剩余动作。

### 6.8 P1-A01 验收标准

- [x] 输入、模型决定、工具调用、工具结果和最终响应都有 Pydantic 模型。
- [x] 所有模型默认拒绝未知字段。
- [x] 前端 TypeScript 类型与后端动作协议一致。
- [x] 未知版本、工具、动作和字段会被拒绝。
- [x] 非法输出安全降级为本地文字和空动作。
- [x] Token、密码和账号信息不会进入模型上下文。

## 七、P1-A02：Agent 工具注册表

### 7.1 注册表职责

注册表是唯一工具入口，负责：

1. 注册工具定义。
2. 按名称查询工具。
3. 校验参数。
4. 调用权限判断器。
5. 执行工具处理器。
6. 校验工具结果。
7. 把异常转换为安全的标准错误。
8. 记录脱敏执行结果。

业务代码不能绕过注册表让模型直接调用 Repository。

### 7.2 每个工具必须声明

| 字段 | 说明 |
|---|---|
| `name` | 稳定、唯一的英文名称 |
| `description` | 给模型看的简短用途 |
| `input_model` | Pydantic 参数类型 |
| `output_model` | Pydantic 结果类型 |
| `side_effect` | 是否改变数据或产品状态 |
| `permission` | 自动允许、明确意图、用户确认或系统专用 |
| `timeout_seconds` | 单工具最大执行时间 |
| `handler` | 实际处理器 |

重复名称必须在应用启动或测试时立即报错。

### 7.3 第一批工具契约

| 工具 | 输入 | 输出 | 是否写数据 | 权限 |
|---|---|---|---:|---|
| `get_today_goal` | 空对象 | 日期和目标文字 | 否 | 自动允许 |
| `set_today_goal` | 目标文字 | 保存后的日期和文字 | 是 | 需要明确用户意图 |
| `get_focus_state` | 空对象 | 当前计时状态摘要 | 否 | 自动允许 |
| `request_start_focus` | 5～120 分钟 | 前端确认动作 | 否 | 必须由用户确认 |
| `request_pause_focus` | 空对象 | 前端确认动作 | 否 | 需要明确用户意图 |
| `complete_focus` | UUID、分钟数和可信计时证据 | 结算结果 | 是 | 仅可信系统调用 |
| `get_study_stats` | 统计范围 | 今日或本周统计 | 否 | 自动允许 |
| `update_preference` | 形象或语音偏好 | 保存后的白名单偏好 | 是 | 需要明确用户意图 |

### 7.4 工具实现规则

- 目标工具复用 `GoalRepository`。
- 统计和完成工具复用 `StudyRepository`。
- 偏好工具新增专用 `PreferenceRepository`，不能直接拼 SQL。
- `get_focus_state` 读取请求携带的受控状态快照，不伪装成服务端已经掌握浏览器计时器。
- 请求开始或暂停只生成待确认动作，不直接控制浏览器。
- `complete_focus` 虽然登记在工具表中，但 P1-A 不允许模型来源执行。
- 所有数据查询都强制使用可信上下文中的 `user_id`，工具参数不接受用户 ID。

### 7.5 工具错误结构

推荐统一为：

```json
{
  "ok": false,
  "error": {
    "code": "TOOL_PERMISSION_DENIED",
    "message": "这个操作需要你先确认"
  }
}
```

允许的错误码至少包括：

- `TOOL_NOT_FOUND`
- `TOOL_INVALID_ARGUMENTS`
- `TOOL_PERMISSION_DENIED`
- `TOOL_TIMEOUT`
- `TOOL_EXECUTION_FAILED`
- `TOOL_INVALID_RESULT`

错误中不能包含数据库地址、SQL、Token、堆栈或模型密钥。

### 7.6 P1-A02 验收标准

- [x] 8 个工具全部通过统一注册表声明。
- [x] 未注册工具无法执行。
- [x] 重名工具注册失败。
- [x] 参数先校验，再判断权限，最后才执行。
- [x] 工具结果经过结构校验。
- [x] 工具异常不会导致聊天接口崩溃。
- [x] 数据工具只访问当前登录用户的数据。
- [x] 工具没有 Shell、文件和任意网络能力。

## 八、P1-A03：状态观察器

### 8.1 观察器的职责

观察器负责把散落在数据库和请求中的状态整理成一份简短、稳定、可校验的 Agent 上下文。

它不是记忆系统，也不是把全部数据库交给模型。

### 8.2 数据来源

| 状态 | 可信来源 | 注意事项 |
|---|---|---|
| 今日目标 | `GoalRepository` | 按用户时区读取当天目标 |
| 今日与本周统计 | `StudyRepository` | 只返回汇总，不返回他人数据 |
| 当前计时状态 | 当前请求的前端快照 | 标记为客户端状态，不能作为结算事实 |
| 搭子和语音偏好 | `PreferenceRepository` | 只返回白名单字段 |
| 最新消息 | 当前请求 | 长度校验后使用 |
| 会话摘要 | 本阶段为空 | P1-C 才真正生成和保存 |

### 8.3 最小披露原则

不得发送给模型：

- 用户名、密码、Token、邀请码。
- 数据库主键和其他内部 ID。
- 完整学习历史明细。
- 全部聊天记录。
- 原始语音或浏览器权限信息。
- 数据库连接信息和错误堆栈。

可发送给模型：

- 今日目标文字。
- 当前计时是否空闲、进行或暂停。
- 剩余时间的有限数字。
- 今日番茄数、今日分钟数、连续天数和本周学习天数。
- 搭子形象和语音开关。

### 8.4 客户端计时状态的信任边界

浏览器当前计时器仍保存在本地，因此观察器只能把它当成“对话参考”，不能当成“结算证据”。

例如：

```text
客户端说正在专注
→ AI 可以回复“那我先安静陪你”
→ 但不能据此增加番茄数
```

正式结算仍走现有 `/stats/complete` 和数据库 `sessionId` 幂等规则。

### 8.5 长度和失败规则

- 观察结构整体序列化后设置大小上限，建议不超过 8 KB。
- 任一可选数据读取失败时使用明确的空值或默认值。
- 身份验证或核心用户状态失败时停止构造，不生成匿名替代用户。
- 数据库不可用时返回安全错误，不把旧 JSON 当作后备事实来源。
- 观察器不执行写操作。

### 8.6 P1-A03 验收标准

- [x] 相同业务状态生成稳定结构。
- [x] 不同用户只能观察自己的目标、统计和偏好。
- [x] 没有目标或偏好时返回合法默认值。
- [x] 客户端计时状态非法时被拒绝或安全归零。
- [x] 上下文超过长度限制时不会直接发送模型。
- [x] 模型上下文中不存在账号密钥和内部数据库信息。
- [x] 观察器全程只读。

## 九、P1-A04：工具权限判断器

### 9.1 权限不能由模型自己声明

模型输出下面这样的内容不能成为授权依据：

```json
{
  "userConfirmed": true
}
```

是否有明确意图、是否已经确认，必须来自后端建立的可信执行上下文。工具参数中出现同名字段也要拒绝。

### 9.2 权限等级

| 等级 | 含义 | 示例 |
|---|---|---|
| `auto` | 只读且仅限本人，可以自动执行 | 读取目标、状态和统计 |
| `explicit_intent` | 当前用户明确提出后才允许 | 修改目标、暂停、修改偏好 |
| `confirmation_required` | 只能返回确认动作，确认前不改变状态 | 请求开始专注 |
| `trusted_system_only` | 模型永远不能直接执行 | 结算专注 |
| `deny` | 未注册、越权或参数危险时直接拒绝 | 任意未知工具 |

### 9.3 权限判断输入

可信权限上下文至少包括：

- 当前登录用户 ID。
- 服务端请求 ID。
- 调用来源：`agent`、`frontend` 或 `system`。
- 当前请求中由程序识别并验证的明确意图。
- 服务器签发的一次性确认凭证；本阶段只定义结构，不接正式 UI。
- 当前工具调用次数和是否已经执行过相同副作用。

这些字段由程序创建，不进入模型工具参数。

### 9.4 工具权限矩阵

| 工具 | Agent 可申请 | 是否直接执行 | 必要条件 |
|---|---:|---:|---|
| `get_today_goal` | 是 | 是 | 已登录，只读本人数据 |
| `set_today_goal` | 是 | 有条件 | 当前用户明确要求修改目标 |
| `get_focus_state` | 是 | 是 | 已登录，请求状态通过校验 |
| `request_start_focus` | 是 | 否 | 只返回前端确认动作 |
| `request_pause_focus` | 是 | 否 | 用户明确提出，仍返回确认动作 |
| `complete_focus` | 否 | 否 | 仅可信计时完成流程可调用 |
| `get_study_stats` | 是 | 是 | 已登录，只读本人数据 |
| `update_preference` | 是 | 有条件 | 用户明确提出具体修改 |

### 9.5 防重复和越权规则

- 相同副作用工具在一次请求中默认最多成功一次。
- 工具参数不能包含 `user_id`；即使模型传入也因未知字段被拒绝。
- 修改目标和偏好必须在数据库事务中完成。
- `complete_focus` 继续依赖数据库唯一约束，权限判断不能代替幂等约束。
- 用户确认凭证必须绑定用户、请求、动作、参数摘要和短有效期。
- 凭证结构可在本阶段定义，实际前端确认流程在 P1-B 完成。

### 9.6 审计记录边界

本阶段记录最小的结构化日志：

- 请求 ID。
- 工具名称。
- 权限判定结果。
- 成功、拒绝、超时或失败。
- 执行耗时。

不记录：

- Token、密码、邀请码或密钥。
- 完整用户消息。
- 完整目标文字和工具参数。
- 数据库错误堆栈对外响应。

`agent_events` 的持久化轨迹属于 P1-C。本阶段可以定义审计接口和测试用内存记录器，但不提前建设完整轨迹系统。

### 9.7 P1-A04 验收标准

- [x] 每个工具都有明确权限等级。
- [x] 模型伪造确认字段不会获得权限。
- [x] 未注册工具、越权用户和非法参数全部被拒绝。
- [x] 需要确认的动作在确认前不改变数据或计时状态。
- [x] `complete_focus` 不能由 Agent 来源直接执行。
- [x] 同一副作用不会在一次请求中重复执行。
- [x] 审计记录不包含秘密和完整用户内容。

## 十、模型调用在本阶段如何处理

当前 `chat.py` 直接调用兼容 OpenAI 格式的聊天接口，并在失败时使用本地话术。

第四阶段允许做的调整：

- 把模型输入和输出解析放入明确的适配层。
- 为结构化响应增加严格 Pydantic 校验。
- 使用假的模型响应测试协议成功和失败。
- 保留现有本地降级能力。

第四阶段不允许：

- 开启真实的多轮工具调用循环。
- 让模型输出的工具调用直接写数据库。
- 自动重试副作用工具。
- 因结构化输出失败而取消现有文字聊天的安全降级。

推荐保持正式 `/api/v1/chat` 的现有用户行为不变，先通过内部服务测试 Agent 基础组件。P1-B 再一次性接入有限循环和前端动作处理器，避免上线一个只能执行半套流程的 Agent。

## 十三、错误处理和安全降级

| 故障 | 安全结果 |
|---|---|
| 模型不可用 | 返回本地陪伴文字，动作为空 |
| 模型输出不是合法协议 | 整包拒绝，返回本地文字 |
| 未知工具 | 返回 `TOOL_NOT_FOUND`，不执行 |
| 工具参数非法 | 返回 `TOOL_INVALID_ARGUMENTS`，不执行 |
| 权限不足 | 返回 `TOOL_PERMISSION_DENIED`，不执行 |
| 工具超时 | 返回 `TOOL_TIMEOUT`，不自动重试副作用 |
| 数据库故障 | 返回安全服务错误，不写回 JSON |
| 客户端状态非法 | 忽略该状态或拒绝请求，不用它结算 |
| 前端不认识动作 | 前端忽略动作，仍显示文字回复 |

任何失败都不能导致：

- 增加错误番茄数。
- 修改他人的目标或偏好。
- 静默开始计时。
- 把内部错误、Prompt 或密钥返回给用户。

## 十五、测试计划

### 15.1 协议测试

- 合法输入和输出通过。
- 缺字段、额外字段、未知版本被拒绝。
- 未知动作和工具被拒绝。
- 动作数量、文字长度和分钟范围超限被拒绝。
- 非 JSON 模型输出进入本地降级。
- 校验失败时没有任何工具副作用。

### 15.2 注册表测试

- 8 个工具名称唯一。
- 重复注册失败。
- 未注册工具执行失败。
- 参数在处理器运行前完成校验。
- 处理器异常被转换成安全错误。
- 结果结构错误被拒绝。
- 副作用工具不被自动重试。

### 15.3 观察器测试

- 正确读取当前用户的目标和统计。
- 用户 A 看不到用户 B 的任何状态。
- 无目标、无统计、无偏好时有稳定默认值。
- 非法客户端计时状态不能成为结算依据。
- 输出不包含用户名、Token、密码和数据库 ID。
- 上下文大小不超过上限。

### 15.4 权限测试

- 只读工具自动允许。
- 修改工具缺少明确意图时拒绝。
- 模型自己声明“已确认”时仍拒绝。
- 开始和暂停只返回确认动作，不改变计时器。
- Agent 来源调用 `complete_focus` 被拒绝。
- 可信系统来源使用合法 UUID 时可幂等结算。
- 越权用户 ID、额外参数和未知工具全部拒绝。
- 相同副作用在一次请求中不会执行两次。

### 15.5 回归测试

完整运行：

```bash
./scripts/verify.sh
```

必须继续保证：

- 注册、登录和退出正常。
- 普通聊天正常，模型失败时仍有本地回复。
- 番茄计时、刷新恢复和幂等结算正常。
- 目标、统计和历史正常。
- 语音关闭后不请求 TTS。
- 前端 lint、生产构建和 Playwright 全部通过。

自动测试不得调用真实模型、TTS 或生产数据库。

## 十八、风险与处理方式

| 风险 | 影响 | 预防 | 出现后处理 |
|---|---|---|---|
| 模型伪造工具或确认 | 越权动作 | 严格协议和可信权限上下文 | 拒绝调用并记录安全结果 |
| 工具重复执行 | 重复写数据 | 请求内去重和数据库幂等 | 返回既有结果，不重复写入 |

| 上下文泄露账号信息 | 隐私风险 | 观察器字段白名单 | 停止发送并补安全回归测试 |
| 客户端伪造计时状态 | 错误结算 | 计时快照只供对话参考 | 拒绝作为完成事实 |
| 工具调用业务逻辑复制 | 数据不一致 | 复用 Repository | 删除重复实现，回归原接口 |
| P1-A 顺手做成完整循环 | 范围失控 | 严格阶段边界 | 拆回 P1-B，不在本阶段合并 |
| 模型失败破坏现有聊天 | 主流程不可用 | 保留本地话术降级 | 回退 Agent 接入点 |
| PostgreSQL 未实库验收 | 生产风险 | 保持隔离开发 | 发布前完成 P0-C 遗留验收 |
