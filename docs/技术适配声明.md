## 1. 产品形态判断

- **产品类型与核心任务**：AI 学习搭子「小悟」——住在 H5「自习室」里的陪学搭子。用户在移动端打开链接进入自习室，完成"定目标 → 番茄钟专注 → 搭子实时鼓励 → 完成打卡庆祝"闭环，获得陪伴与情绪价值。**明确不做学科答疑**（搭子是"同伴"不是"老师"）。
- **核心交互**：多轮对话 + 定时触发式陪伴（番茄钟开始/过半/结束触发搭子说话 + 用户主动聊天/快捷按钮）。
- **开发路径**：**后端先行（本阶段）**。已存在的 H5 是已落地的纵向切片；本阶段把核心能力下沉为 FastAPI 后端 API，前端改为薄客户端调 API。理由：① 模型 Key 必须从浏览器移到后端（强制底线"模型 Key 只能由后端读取"）；② 核心能力需 API 化以便复用、自动化验证与未来多端/云同步扩展。
- **当前阶段范围**：后端开发（核心能力 API 化 + 前端联调 + 默认模型 + 计时恢复 + 双层验收）。**本阶段不做部署、不做埋点。**

## 2. 采用的默认方案

- **Python 3.11.16 + FastAPI + Pydantic + pytest**：B 默认方案，符合手册；环境实测 `/Users/Admin/.local/bin/python3.11`（3.11.16）。
- **OpenAI 兼容模型调用**（`httpx` 调 `/chat/completions`）：B 默认方案（"经过验证的兼容接口"）。
- **结构化文件持久化**（JSON + schemaVersion + 原子写入）：C 按需模块，单用户、简单数据（stats/goal）触发，不引入数据库。
- **Git 版本管理**：A 强制底线，本阶段初始化 + `.gitignore`。
- **`.env` 存密钥**：A 强制底线，模型 Key 只存后端、不进入前端代码与仓库。

## 4. 偏离或暂缓的默认方案

| 手册默认 | 本阶段替代 | 原因 | 恢复条件 |
|---|---|---|---|
| Next.js + TS + Tailwind 正式前端 | 原生 HTML/CSS/JS 单文件（改为调后端 API） | 延续已落地 H5，避免为符合手册目录而整体重构 | 需要工程化前端 / 组件库 / 复杂状态管理时迁移 |
| 关系型数据库 | 结构化 JSON 文件（schemaVersion + 原子写入） | 单用户、数据简单、无并发修改 | 出现多用户、复杂查询或并发修改时按手册迁移 SQLAlchemy + Alembic |
| 部署（静态托管） | 暂缓 | 产品经理决定先做后端、后部署 | 后端验收通过后进入部署阶段 |

## 5. 强制底线检查

- **密钥与隐私**：✅ **本阶段改进**——模型 Key 从"前端 localStorage 直连"移到"后端 `.env`"，符合"模型 API Key 只能由后端读取、不能进入前端"底线。`.env` 加入 `.gitignore`，只提交 `.env.example`。
- **数据与任务可恢复**：✅ stats/goal 存后端 JSON 文件（原子写入 + schemaVersion，进程重启可恢复）；进行中的番茄钟计时由前端 localStorage 持久化（刷新恢复，写绝对结束时间戳）。
- **输入输出校验**：✅ API 用 Pydantic 校验请求结构；聊天 maxlength、模型空回复回退内置引擎。
- **错误与日志边界**：✅ 统一错误结构 `{"error": {"code","message"}}`，不向用户暴露堆栈；模型调用失败回退内置引擎，不中断体验。
- **测试与真实模型验收**：✅ 第一层 pytest mock 全绿（33 passed，离线可跑）+ 第二层真实 Key 冒烟通过（GLM-4-Flash 跑通"输入→真实模型→回复"）。**无真实 Key 时明确声明"冒烟待验"，不得用 mock 冒充。**
